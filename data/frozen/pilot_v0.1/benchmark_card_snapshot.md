# Benchmark Card: CausalAgentBench

## Intended Use

CausalAgentBench evaluates tool-using agents on paired clean and intervened tasks. It is intended for controlled research on whether final task success survives perturbations to planning, tool availability, observations, memory, recovery, and stopping signals.

## Out-of-Scope Use

This first version is not a leaderboard and should not be used to claim real-world agent superiority. The included tasks are deterministic synthetic seeds for smoke testing, method development, and reproducibility auditing.

## Construction Process

Generated benchmark data is built from deterministic domain templates covering travel, calendar/email, file/spreadsheet QA, shopping/comparison, research assistant, policy/compliance, coding/debugging, and multi-hop operations. Configs specify the seed, number of base tasks, domain set, difficulty mix, interventions per task, and output directory. Frozen bundles use disjoint `dev`, `pilot`, `validation`, `test`, and `heldout_templates` splits.

Each generated base task has a clean instance. Intervention variants are generated by applying a targeted patch where possible. Quality checks flag missing expected answers, missing required tools, multi-factor interventions, impossible step budgets, ambiguous success criteria, tool-sequence mismatches, missing expected intervention behavior, and duplicate instances.

## Data Fields

Benchmark instances include a base task, condition, optional intervention spec, available tools, initial memory, environment seed, and metadata. Trajectories include actions, tool calls, observations, final answer, termination reason, and run metadata. Scores include per-instance metrics and diagnostics.

## Evaluation Metrics

Core metrics include final task success, required-tool recall, tool precision, unnecessary-tool-call rate, argument validity, recovery rate, contradiction detection and resolution, memory verification, premature stopping, trajectory faithfulness, ACRS, per-family ACRS, degradation, and ranking instability.

## Known Limitations

Synthetic tools may understate ambiguity and distribution shift. Template generation can introduce repeated patterns. Oracle-style agents use task metadata and should be treated as sanity checks only. Passing quality checks does not replace human validation. Controlled interventions require audit before strong causal claims.
