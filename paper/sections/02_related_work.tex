\section{Related Work}

\paragraph{Agent and tool-use benchmarks.}
Existing agent benchmarks evaluate web navigation, software engineering, tool use, planning, and multi-step task completion. The related-work tracker in \texttt{docs/RELATED\_WORK\_TRACKER.md} lists the papers and benchmarks that must be reviewed before submission. This draft intentionally uses TODO bibliography entries rather than invented citations \citep{todo_agent_benchmark_survey,todo_tool_use_benchmarks,todo_web_navigation_benchmarks,todo_software_agent_benchmarks}.

\paragraph{Trajectory-level evaluation.}
Several evaluation efforts inspect intermediate reasoning, actions, or traces rather than only final answers. \benchmark builds on that idea by treating trajectory metrics as diagnostics for separable agent skills rather than as a replacement for final task success. The planned evidence for this distinction is tracked by \claimref{C3}.

\paragraph{Robustness and causal/intervention-based evaluation.}
Robustness benchmarks often vary input phrasing, distribution, adversarial examples, or environment state. \benchmark focuses on paired task instances where a targeted factor is changed while the high-level user goal is held fixed. The intended contribution is not merely harder tasks, but a causal comparison between clean and intervened conditions. This is the basis of \claimref{C1}, \claimref{C2}, and \claimref{C10}.

\paragraph{Why paired interventions are scientifically different.}
The central distinction is the estimand. A standard perturbation benchmark asks whether an agent's score changes on a harder or shifted dataset. \benchmark asks whether a specific agent skill survives when a named factor is intervened on while the user goal and base task are held fixed. This does not automatically prove causality; it creates an auditable design where intervention validity can be inspected and challenged. The final paper must show that this design yields information not captured by aggregate success alone.

\paragraph{LLM-as-judge and human validation.}
Final-answer and trajectory labels can be exact, heuristic, human-annotated, or model-judged. The default \benchmark smoke path uses deterministic scoring only. If LLM-as-judge scoring is added, the paper must report grader prompts, model versions, agreement rates, and failure modes, and must not treat judge labels as ground truth without validation. Human validation is planned under \claimref{C3} and \claimref{C10}.
