\section{Related Work}

\paragraph{Agent benchmarks.}
AgentBench evaluates language models across multiple interactive environments and reports aggregate success \citep{liu2025agentbenchevaluatingllmsagents}; it is relevant because it established multi-environment agent evaluation, while \CAB{} holds the user goal fixed and pairs clean with single-factor interventions to attribute drops to named tool-using skills rather than only reporting lower aggregate success.
GAIA targets assistant questions that require reasoning, multimodality, web browsing, and tool use \citep{mialon2023gaiabenchmarkgeneralai}; it is relevant as a realistic assistant benchmark, while \CAB{} trades some open-world realism for auditable perturbations of tools, memory, and evidence in a deterministic simulator.
AgentBoard scores multi-turn agents with progress-rate and sub-skill breakdowns beyond a single terminal success bit \citep{ma2024agentboardanalyticalboardmultiturn}; it is relevant for trajectory-aware evaluation, while \CAB{} adds paired intervention instances and component metrics tied to recovery, memory verification, and contradiction handling rather than only finer-grained success curves on unperturbed tasks.

\paragraph{Tool-use benchmarks.}
Toolformer studies self-supervised learning of when and how to call external APIs \citep{schick2023toolformerlanguagemodelsteach}; it is relevant for tool-call learning, while \CAB{} evaluates whether an already prompted agent survives controlled tool failures, corruptions, and removals at task time.
ReAct interleaves reasoning traces with environment actions \citep{yao2023reactsynergizingreasoningacting}; it is relevant as a trajectory-explicit prompting method, while \CAB{} treats the executable action trace as the primary measurement object under intervention rather than proposing a new prompting recipe.
API-Bank benchmarks tool-augmented dialogues with planning, retrieval, and calling \citep{li2023apibankcomprehensivebenchmarktoolaugmented}; ToolLLM/ToolBench scales API-use data and evaluation over many real-world APIs \citep{qin2023toolllmfacilitatinglargelanguage}; and Gorilla/APIBench focuses on API selection and call generation from documentation \citep{patil2023gorillalargelanguagemodel}---all are relevant comparators for tool-call competence, while \CAB{} emphasizes paired perturbations (unavailable tools, bad arguments, corrupted observations) and trajectory-level recovery diagnostics.
StableToolBench targets stable large-scale tool-learning evaluation by reducing API instability and response variance \citep{guo2024stabletoolbenchstablelarge}; it is relevant because benchmark noise can confound tool-use scores, while \CAB{} injects named, auditable failures in a small deterministic tool universe to study robustness rather than only reducing external API drift.
$\tau$-bench evaluates agents that must follow domain policies while interacting with simulated users and database APIs \citep{yao2024taubenchtoolagentuser}; it is relevant for user-in-the-loop tool agents, while \CAB{} does not simulate free-form user dialogue but instead perturbs tool outputs, memory, and contradictory evidence while keeping the stated task goal fixed.

\paragraph{Web navigation benchmarks.}
World of Bits and workflow-guided MiniWoB-style interfaces study web agents over DOM or pixel actions in reproducible simulated sites \citep{shi2017worldofbits,liu2018reinforcementwebinterfaces}; they are relevant as early controlled web environments, while \CAB{} focuses on modern LLM tool protocols and intervention families not limited to click sequences.
Mind2Web collects diverse real websites and action traces for generalist web agents \citep{deng2023mind2webgeneralistagentweb}; it is relevant for open-web diversity, while \CAB{} prioritizes paired causal perturbations over site coverage.
WebArena provides a realistic, reproducible browser environment for autonomous web agents \citep{zhou2024webarenarealisticwebenvironment}; WebShop scales grounded product-search dialogues in a simulated e-commerce site \citep{yao2022webshoptowardsscalablereal}; and VisualWebArena adds visually grounded realistic web tasks \citep{koh2024visualwebarenaevaluatingmultimodal}; these are important external-validity comparators, while \CAB{} starts from deterministic local tools and optional frozen web snapshots so that intervention patches remain inspectable.
OSWorld benchmarks multimodal agents on open-ended tasks in real desktop environments \citep{xie2024osworldbenchmarkingmultimodalagents}; it is relevant for high-fidelity computer-use evaluation, while \CAB{} deliberately narrows environment complexity to make single-factor interventions and trajectory attributions auditable before scaling to full GUI realism.

\paragraph{Software engineering agents.}
SWE-bench evaluates whether models can resolve real GitHub issues via code changes in repository environments \citep{jimenez2024swebenchlanguagemodelsresolve}; it is relevant because software agents combine planning, retrieval, editing, and tool use under noisy real artifacts, while \CAB{} uses smaller synthetic debugging-style tasks to isolate tool-memory-contradiction failures before claiming transfer to repository-scale SWE settings.

\paragraph{Process and trajectory evaluation.}
Process-supervision work trains verifiers to judge intermediate reasoning steps rather than only final answers \citep{lightman2023letsverifystepstep}; it is relevant because outcome-only scores can hide reasoning errors, while \CAB{} scores executable tool calls, arguments, observations, recovery moves, and stopping decisions in a simulated tool environment rather than mathematical chain-of-thought steps alone.
ReAct and AgentBoard (above) further motivate logging multi-step behavior; \CAB{} uses the same motivation but ties trajectory metrics to survival under named interventions, as planned in \claimref{C3}, without presenting those diagnostics as substitutes for task success.

\paragraph{Robustness and perturbation evaluation.}
HELM advocates multi-metric, multi-scenario language-model evaluation \citep{liang2023holisticevaluationlanguagemodels}, and BIG-bench collects broad tasks for capability probing \citep{srivastava2023imitationgamequantifyingextrapolating}; both are relevant for holistic robustness framing, while \CAB{} applies paired perturbations within a single agent task distribution rather than aggregating unrelated stress tests.
DecodingTrust systematically stress-tests GPT models across toxicity, bias, privacy, adversarial prompts, and out-of-distribution settings \citep{wang2023decodingtrustcomprehensiveassessment}; it is relevant for showing that aggregate capability can mask fragility under shift, while \CAB{} narrows stress tests to tool-using agent trajectories---tool failure, memory corruption, contradictory evidence---with clean/intervention pairing on the same base task.

\paragraph{Causal and interventional framing.}
Causal-inference traditions distinguish observed associations from outcomes under alternative conditions \citep{holland1986statisticscausalinference,pearl2009causality}; they are relevant for the language of interventions and counterfactual comparison, while \CAB{} does not claim to identify deployment-wide causal effects from observational logs but instead constructs paired instances whose estimand is explicit: whether measured agent behavior changes when a named factor in a controlled simulator is changed.
The validity of this interpretation depends on intervention audits, documented patch details, and human validation (\claimref{C10}), not on importing full causal-identification machinery into benchmark scoring.

\paragraph{LLM-as-judge and human validation.}
LLM-as-judge methods scale preference and quality evaluation and report agreement with human raters on chat tasks \citep{zheng2023judgingllmasajudgemtbenchchatbot}; they are relevant when trajectory or intervention validity must be labeled at scale, while \CAB{} defaults to deterministic scoring for smoke and reproducibility paths and treats any future model judge as supplementary---requiring judge prompts, model versions, agreement rates, and failure-mode reporting, and not replacing human validation for intervention validity.
Judge bias, prompt sensitivity, and circular evaluation when similar models serve as both agent and judge remain active risks for any LLM-judge extension of this benchmark.

\paragraph{Artifact and reproducibility practice.}
Recent artifact-evaluation norms emphasize versioned code, environment capture, and honest scope statements for benchmark papers \citep{liang2023holisticevaluationlanguagemodels}. \CAB{} adopts this practice through release manifests, reproducibility bundle plans, CI fast-checks, and explicit evidence-level labels, but these engineering measures do not replace missing empirical results.
