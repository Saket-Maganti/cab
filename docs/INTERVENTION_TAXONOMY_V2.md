# Intervention Taxonomy V2

Status: no-execution taxonomy upgrade. Families marked `candidate` are design proposals and are not generated evidence.

| family | intended factor changed | invariants | expected failure mode | valid examples | invalid/confounded examples | scorer risks | human-review questions | exclusion criteria |
|---|---|---|---|---|---|---|---|---|
| tool_removal | useful tool availability | user goal, hidden truth, remaining tools, scoring policy | brittle dependence on unavailable route | remove one helpful non-unique tool and allow alternate route or limitation | remove all possible evidence routes while requiring definitive answer | false failure if abstention is valid | Is the same goal still answerable or safely abstainable? | no valid path and no abstention policy |
| tool_failure | tool reliability | tool list, goal, hidden truth | repeated failed calls, no recovery | required tool returns explicit transient error | also removing the tool or changing answer | recovery keywords may be missed | Did the agent have a reasonable recovery route? | failure makes task impossible without policy |
| tool_corruption | tool output correctness | tool list, goal, hidden truth | blind trust in wrong observation | one tool returns plausible wrong value | hidden answer changed to match corruption | substring scorer may reward corrupted answer | Is the corrupted output detectable or cross-checkable? | corruption creates second valid answer |
| irrelevant_tools | distractor tool availability | required tools, ground truth, success policy | over-tooling | add irrelevant but harmless tool | add a tool that reveals answer | precision may over-penalize exploration | Is the added tool truly irrelevant? | added tool changes evidence access |
| memory_corruption | memory correctness | current evidence, goal, tools | stale-memory blind trust | stale preference conflicts with current record | current truth changed to make memory true | implicit verification undercounted | Should current evidence override memory? | no way to verify memory |
| observation_conflict | observation consistency | goal, tool list, underlying truth | unqualified answer despite conflict | two sources disagree on same field | unsignaled impossible task | paraphrased conflict handling missed | Did the task permit uncertainty or resolution? | conflict cannot be resolved or bounded |
| ambiguous_instruction | instruction specificity | high-level goal, evidence, tools | premature assumption | omit one preference criterion | ask a different question | clarification may be mis-scored as failure | Is clarification acceptable? | ambiguity changes target task |
| long_horizon_dependency | dependency length | goal, tools, answer | lost intermediate evidence | require earlier evidence in later step | change final answer while adding dependency | long trajectories may be penalized unfairly | Is the dependency necessary and isolated? | max steps make success impossible |
| premature_success_signal | completion signal | goal, hidden truth, success criteria | stops before evidence complete | environment says done too early | changing success criteria to match signal | scorer may miss stop rationale | Was the signal misleading but goal-preserving? | no clear continuation requirement |
| distractor_evidence | evidence relevance | required evidence, goal, answer | attends to irrelevant context | add plausible but irrelevant record | distractor is another valid answer | substring false positives | Can a reviewer identify correct evidence? | distractor alters gold answer |
| tool_unavailability | candidate: temporary unavailable tool state | goal, tool schema, gold policy | failure to route around unavailable state | tool returns unavailable for this session | permanent removal plus schema change | same as tool_removal | Is unavailability distinct from removal? | duplicates tool_removal without rationale |
| tool_latency_failure | candidate: delayed/timeout tool behavior | goal, output correctness | no retry/backoff | timeout then alternate evidence route | timeout plus corrupted output | latency metadata missing | Was timeout behavior auditable? | no timestamp/error record |
| stale_memory | candidate: outdated memory | current evidence, goal | outdated preference or policy use | previous calendar state conflicts with current | hidden truth changed to memory | same as memory_corruption | Was current evidence available? | no verification route |
| conflicting_observation | candidate: explicit contradiction | underlying truth, goal | no conflict resolution | database and email disagree | changed user goal | keyword scorer fragility | Did response qualify uncertainty? | contradiction impossible to adjudicate |
| misleading_tool_output | candidate: plausible but wrong tool output | goal, tool availability | tool-output overtrust | wrong total from calculator with cross-check route | two wrong outputs and changed answer | exact match may miss near miss | Is a cross-check expected? | no independent check |
| hidden_environment_state_change | candidate: state changes outside prompt | goal, user instruction | stale plan after environment update | inventory changes between calls | changing hidden target without signal | hard to score without logs | Is state change observable? | unobservable and unfair |
| partial_observability | candidate: insufficient evidence | goal, tools, policy | overconfident answer | missing field requires caveat | missing evidence but definitive gold | abstention handling required | Is abstention correct? | scorer lacks abstention policy |
| irrelevant_distractor_context | candidate: irrelevant prompt context | goal, evidence | context distraction | unrelated memo in prompt | memo contains valid answer | false positive substring risk | Is distractor clearly irrelevant? | distractor changes interpretation |
| adversarial_goal_preserving_instruction | candidate: adversarial phrasing without goal change | goal, tools, truth | instruction-following brittleness | pressure to skip verification | asks different task | refusal vs compliance ambiguity | Does adversarial text preserve goal? | policy/safety issue dominates |
| recovery_after_error | candidate: designed recoverable error | goal, tools, truth | failure to recover | first call fails, second route works | all routes fail | recovery scorer undercounts | Was a recovery route obvious? | no recovery route exists |
| abstention_required_ambiguity | candidate: insufficient info by design | goal, evidence limits | unsafe fabrication | missing required input, correct response asks clarification | hidden answer available but withheld | over-reward refusal | Is abstention/clarification the intended gold? | ambiguity not documented |

## Policy

Candidate families require schema update, generator support, fixture tests, and human review before inclusion in Compact-20 or larger runs. They are currently research design inventory only.
