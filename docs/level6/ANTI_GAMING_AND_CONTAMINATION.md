# Anti-Gaming and Contamination Governance

CAB separates public development tasks, private validation tasks, rotating
protected tasks, challenge tasks, and temporal holdouts. Public commitments may
identify pool versions and hashes but never protected task bodies.

Canaries include prompt fragments, unique synthetic strings, artifact
fingerprints, answer canaries, and metadata canaries. Their plaintext is kept in
protected storage; public code handles commitments. Scans cover the repository,
governed web searches, benchmark overlap, output anomalies, memorization
indicators, and suspicious near-perfect behavior. A match is an investigation
signal, not automatic proof of misconduct.

Submissions are bound to system identity, rate limited, throttled, and capped for
retries. Suspicious behavior may trigger hidden challenges, temporary
suspension, preserved receipts, non-conflicted review, and appeal.

Task replenishment proceeds through proposal, provenance and licence checks,
semantic review, calibration, protected ingestion, version promotion, monitoring,
deprecation, and retirement. Protected exposure propagates to descendants.
